## Corrections effectuées

- `fund-collections` : préciser que Set et Map possèdent aussi un ordre d’insertion. L’ancienne recommandation pouvait faire croire que seuls les tableaux conservaient un ordre. Source : [ECMAScript, collections](https://tc39.es/ecma262/multipage/keyed-collections.html).
- `js-await` : ajouter `return data` pour que l’exemple corresponde au résultat évoqué par la question ; expliciter l’ordre garanti dans le scénario de promesse, même déjà accomplie. Source : [ECMAScript, Await](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#await).
- `ui-box-model` : remplacer la troisième carte, qui répétait la première sous forme oui/non, par un calcul de largeur totale incluant les marges. Le concept rappelé reste identique. Source : [CSS UI, box-sizing](https://www.w3.org/TR/css-ui-3/#box-sizing), consultée pour ce contrôle complémentaire.
- `sql-keys` : distinguer un ID référencé inexistant d’une valeur NULL autorisée sans NOT NULL ; identifier l’exemple comme extrait de schéma. Source : [PostgreSQL, contraintes](https://www.postgresql.org/docs/current/ddl-constraints.html).
- `docker-images-containers` : remplacer l’étape de remédiation répétant presque mot pour mot la conclusion commune par l’explication du redémarrage des processus. Source : [Docker, container restart](https://docs.docker.com/reference/cli/docker/container/restart/).
- `docker-volumes-persistence` : ajouter la sauvegarde et la migration des données de la couche modifiable avant suppression. Créer un nouveau conteneur avec un volume ne récupère pas automatiquement les données du précédent. Source : [Docker, volumes](https://docs.docker.com/engine/storage/volumes/).

## Recouvrements pédagogiques conservés

`js-promise` introduit l’issue ; `js-await` explique la continuation ; `js-async-errors` place le gestionnaire au bon endroit. `ts-narrowing`, `ts-unknown` et `ts-runtime` se recoupent sur la validation mais interrogent respectivement la preuve de type, une valeur externe et le moment de validation. `react-derived-state` et `react-effects-sync` réemploient le calcul pendant le rendu pour des objectifs distincts. Les transactions SQL/Firestore et les reprises backend reprennent concurrence et effet externe dans des systèmes aux garanties différentes. Aucun doublon textuel exact de question n’a été observé dans le lot.

Réserve de forme : de nombreux distracteurs opposent une solution correcte à un choix assez manifestement faux. Les questions vérifient donc surtout la compréhension initiale. La difficulté devra être évaluée avec des apprenants ; les défis libres apportent une application plus ouverte. Pas de remplacement d’objectif ou de suppression de carte pour modifier artificiellement la difficulté.
